## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | 성취기준 연계 에듀테크 교수학습과정안·활동지 자동 생성 시스템 |
| 요구사항 ID | REQ-006 |
| 요구사항명 | 사이트 전반 로직 및 인프라 |

| 담당자 | 김준명 (E) |
| 작성일 | 2026-08-02 |
| 문서 버전 | v1.0 |

본 문서는 각 에이전트가 협업하는 공통 기반(DB 연결, LLM 호출, 타입 계약)과 이 서비스를 실제 사용자에게 노출하는 웹 인터페이스 셸, 그리고 Cloud Run 배포 전반에 대한 요구사항을 정의한다. 검증·오케스트레이션 로직은 REQ-003(D) 문서에서 별도로 다룬다.

**핵심 설계 원칙**

- 인프라 최소 구성: 별도 서버(Compute Engine, 별도 백엔드 프레임워크) 없이 단일 Cloud Run 서비스로 배포를 완결한다.
- 공통 유틸리티 집중 관리: DB 연결·LLM 호출·타입 계약처럼 여러 에이전트가 공유하는 코드는 `lib/`에 모아 중복을 방지한다.
- 파일 소유 경계: E는 `main.py`, `lib/`, `static/`, `templates/`, 배포 파이프라인을 소유하며, 판단 로직(`agents/validate/`, `agents/orchestrate.py`)은 D(REQ-003)가 소유한다.
- 도메인 연결 안정성: GCP 네이티브 도메인 매핑 대신 Cloudflare 프록시를 경유하여 SSL 발급 지연 리스크를 회피한다.

**하위 기능 구성**

- INFRA-001: 배포 아키텍처
- INFRA-002: 공통 유틸리티
- SITE-001: 웹 인터페이스 셸

---

### 1. 배포 아키텍처 (INFRA-001)

단일 FastAPI 서비스를 Cloud Run에 배포하고, Cloud SQL(A2가 구축한 `curriculum_chunks` 포함)과 Gemini API에 연결한다.

| 항목 | 내용 | 핵심 포인트 | 비고 |
| --- | --- | --- | --- |
| 입력 | 소스 코드(GitHub main 브랜치) | PR 머지 시 자동 반영 | 브랜치 보호 규칙 적용, D/E는 Admin 우회 권한 보유 |
| 처리 | Cloud Build 트리거로 Dockerfile 빌드 → Cloud Run 신규 리비전 배포 | 별도 Compute Engine·Spring 불필요 | 서버리스, 요청 시에만 실행 |
| 출력 | `*.run.app` 주소, Cloudflare로 커스텀 도메인 연결 | run.app 자체는 배포 즉시 HTTPS 적용 | 도메인은 Cloudflare 프록시 경유(GCP 네이티브 도메인 매핑의 지연 리스크 회피) |
| 예외 처리 | 빌드 실패 시 이전 리비전 유지(자동 롤백) | 배포 실패가 서비스 중단으로 이어지지 않음 | Cloud Run 기본 동작 |

---

### 2. 공통 유틸리티 (INFRA-002)

여러 에이전트가 공유하는 DB 연결, LLM 호출, 타입 계약을 제공한다.

| 파일 | 역할 | 사용처 |
| --- | --- | --- |
| `app/lib/db.py` | Cloud SQL 연결 헬퍼 | A2(검색·적재), D(검증 시 금지 용어 리스트 조회) 등 DB가 필요한 모든 에이전트 |
| `app/lib/gemini.py` | Gemini API 호출 공통 함수(에러 처리·재시도 포함) | A1, B, C, D(2단계 검증) 등 LLM 호출이 필요한 모든 에이전트 |
| `app/lib/types.py` | 전역 공통 타입 정의 | 전체 에이전트. 1일차 전원 합의, 이후 변경 시 전원 합의 필요 |

| 항목 | 내용 | 핵심 포인트 | 비고 |
| --- | --- | --- | --- |
| 입력 | 각 에이전트로부터의 DB 쿼리·API 호출 요청 | 에이전트별 중복 구현 방지 | - |
| 처리 | 연결 관리, 재시도 로직, 공통 예외 처리를 한 곳에서 담당 | 개별 에이전트는 비즈니스 로직에만 집중 | - |
| 출력 | 정상 응답 또는 표준화된 에러 | 에이전트 간 에러 처리 방식 통일 | - |
| 예외 처리 | API 실패 시 지정된 횟수만큼 자동 재시도 후 에러 반환 | 개별 에이전트가 재시도 로직을 각자 구현하지 않도록 함 | - |

### 3. 웹 인터페이스 셸 (SITE-001)

사용자가 AI 개념과 학년을 입력하고 결과를 확인하는 화면 골격을 제공한다.

| 항목 | 내용 | 핵심 포인트 | 비고 |
| --- | --- | --- | --- |
| 입력 | 사용자 폼 입력(AI 개념, 학년) | Jinja2 서버사이드 렌더링 | `app/templates/index.html` |
| 처리 | 폼 제출 시 D의 오케스트레이터(ORCH-001) 호출, 결과 대기 | 파이프라인 처리 중 로딩 상태 표시 | 필요 시 htmx로 보강 |
| 출력 | 교안·활동지 결과 화면 | `app/templates/result.html` | 세부 렌더링은 C가 소유, 골격은 E가 제공 |
| 예외 처리 | 파이프라인 실패 시 사용자 친화적 에러 메시지 표시 | 스택트레이스 노출 금지 | - |

## 3. 기술 스택

| 영역 | 기술 | 선정 사유 |
| --- | --- | --- |
| 웹 프레임워크 | FastAPI, Jinja2 | 팀 전체 언어 통일(Python), 서버사이드 렌더링으로 구성 단순화 |
| 데이터베이스 | Cloud SQL(PostgreSQL) + pgvector | A2와 스키마 공유 |
| LLM | Gemini API | GCP 크레딧 활용, 생성·임베딩 전체 통일 |
| 배포 | Google Cloud Run | 서버리스, 별도 서버 관리 불필요 |
| 도메인 | Cloudflare | 빠른 SSL 발급, GCP 네이티브 도메인 매핑의 지연 리스크 회피 |
